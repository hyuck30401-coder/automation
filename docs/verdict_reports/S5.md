# §S5 — "계산 불가"를 0.0 대신 None 으로

## 1. 수정 전, 0.0 을 반환하던 함수/조건 (전수 점검 결과)

`stats_core.py`:
| 함수 | 조건 | 수정 전 | 수정 후 |
|---|---|---|---|
| `mean_of` | 유효값 0개 (빈 입력 또는 전부 None/nan/inf) | `0.0` | `None` |
| `std_of` | `n - ddof <= 0` (표본 부족, 예: n=1, ddof=1 기본값) | `0.0` | `None` |
| `std_of` | 유효값 0개 | `0.0` | `None` |
| `zscore` | `spread == 0` (0/0 형태, 각 원소별) | `0.0` | `None` |
| `zscore` | `center is None` 또는 `spread is None` | (이미 방어 없었음 → 예외 위험) | `None` |
| `max_abs_z` | 유효 zscore 후보 0개 (빈 입력, 전부 None, 또는 spread=0) | `0.0` | `None` |

`cdf_compare_web.py`:
| 함수 | 조건 | 수정 전 | 수정 후 |
|---|---|---|---|
| `max_abs_finite` | 유한값 0개 | `0.0` | `None` |

검토했으나 **변경하지 않은** 0.0 반환 지점 (정의상 진짜 0이지 "계산 불가"가 아님):
- `normal_cdf_value` / `normal_cdf`(`-inf → 0.0`): 정규분포 CDF의 수학적 극한값, 계산 불가가 아님.
- `spec_margin_ratio`: 스펙 마진이 정말 0인 경우의 정상값.
- `over_sigma_rows`의 정렬 키 fallback `0.0`: 정렬 전용 내부 키이며 화면/판정에 노출되지 않음.

## 2. 호출부 정리 (grep 카운트)

- `stats_core` 4개 함수의 직접 호출부: `mean_of`/`std_of`/`zscore`/`max_abs_z` 합계 **9곳** (`cdf_compare_web.py` 5곳, `cdf_compare_tool.py` 4곳) — 모두 `vector_stats`/`vector_sigmas`/`item_mean_sigma` 류의 얇은 래퍼를 통해 하위로 전파됨.
- 그 값(`post_mean`/`post_sigma`/`diff_mean`/`diff_sigma`/`mea_s_values`/`diff_s_values`)을 소비하는 2차 호출부: `vector_stats`/`vector_sigmas`/`max_abs_finite` 사용처 **20곳**.
- 최종 소비처 `flag_result(...)` 호출 **11곳** — §S3 에서 이미 None-tolerant 하게 만들어진 `_branch_status` 로 귀결되므로 별도 수정 불필요.
- None 과의 직접 산술(`+ - * /`) 검색 결과, 가드 없이 연산하는 곳 **0곳** (유일한 산술 지점 `cdf_compare_web.py:5926`의 `post_mean - pre_mean` 은 이미 `is not None` 가드 존재).
- 프론트엔드 JS: `finiteNumber`/`numericValues` 헬퍼 사용처 각각 26곳/16곳. 이 두 헬퍼 자체에 있던 `Number(null) === 0` 강제형변환 버그(그래프에 None 이 0으로 찍히는 원인)를 수정. 이 버그를 우회해서 직접 `Number(...).filter(Number.isFinite)` 패턴을 쓰던 지점 6곳(산점도 필터 3곳, Diff CDF `values` 1곳, `passValues` 1곳, 하이라이트 포인트 diff 계산 1곳)을 `finiteNumber`/`numericValues` 경유로 교체. 수정 후 동일 패턴 잔존 **0곳** (grep 확인).
- `summaryCellValue`의 `qty_ratio`/`diff_mean` 두 곳도 같은 버그로 None 을 "0.0%"로 표시하고 있어 수정.

## 3. 화면·내보내기 반영

- Summary/Detail 표: `fmtCell()` 신설, `td.textContent`가 `fmt()` 대신 `fmtCell()`을 사용하도록 2곳 교체 → None/NaN 은 "N/A".
- 항목 판정: §S3 에서 만든 `NOT EVALUATED` 상태를 그대로 재사용 (`_branch_status`의 sigma 체크가 z 체크보다 먼저 실행되도록 이미 정렬되어 있어, `zscore`가 새로 `None`을 반환해도 `NOT EVALUATED`로 정상 낙하함 — 신규 상태 추가 없음).
- Excel: `xlsx_cell()`이 `value is None`일 때 이미 `<c>` 엘리먼트 자체를 생략하고 `""`를 반환 — **기존 코드가 이미 요건을 만족**하고 있어 코드 변경 없음 (검증만 수행).
- CSV(`cdf_compare_tool.py`의 `export_csv`)도 `fmt(None) == ""` 경로로 이미 빈칸 — 코드 변경 없음.
- 그래프: `finiteNumber`/`numericValues` 수정으로 None 값이 `Number()`를 거치기 전에 걸러져 점이 찍히지 않음 (산점도, Diff CDF 차트, 하이라이트 포인트 전부 적용).

## 4. 검증 결과

### 4-1. 단위 테스트 (`tests/test_stats_core.py`)
전체 통과 (0 실패). None 반환 케이스 커버리지:
- `mean_of([])`, `mean_of([nan, inf])` → `None`
- `std_of([])`, `std_of([5.0])` (n=1, ddof=1 기본값) → `None` / `std_of([5.0], ddof=0) == 0.0` (진짜 계산된 0, 대조 케이스)
- `zscore([5.0], 3.0, 0.0) == [None]` (spread=0), `zscore(.., None, 1.0)`/`zscore(.., 0.0, None)` → 전부 `None`
- `max_abs_z([], ..)`, `max_abs_z(.., spread=0)` → `None`
- **통합 회귀 테스트 3건 신규 추가**: `flag_result(mode="grubbs")`에서 `sigma=None`(z가 유한값이어도), `sigma=None and z=None`, 그리고 실제 `mean_of`→`std_of`→`zscore` 체인을 그대로 이어붙인 케이스 모두 `"NOT EVALUATED"`로 떨어지는지 확인 — §S3 `_branch_status` 재정렬이 §S5 변경과 맞물려도 `"OK"`로 새지 않음을 실증.

### 4-2. Test Data — `tests/verdict_base_S4` 대비 (`docs/verdict_reports/S5.md` 자체 비교 실행 결과)
```
SELECT      223 → 223    (+0)
OK          246 → 246    (+0)
판정불가(NOT EVALUATED)  2 → 2      (+0)
```
전이 행렬: 대각선 외 전부 0 (OK→OK 246, SELECT→SELECT 223, NOT EVALUATED→NOT EVALUATED 2). 신규/삭제 항목 없음.

항목 딕셔너리 비교 자체는 "차이 있음"으로 표시되는데, 이는 이미 `NOT EVALUATED`였던 항목 2개(총 114개 sample-row)의 내부 수치 필드(`mea_s`/`diff_s`)가 `0.0`→`None`으로 바뀐 것일 뿐, `result` 문자열(전부 `"NOT EVALUATED"`)은 변경 전후 동일함을 직접 확인함. 즉 라벨 전이는 0건.

### 4-3. Perf Data — 임시 pre-S5 베이스라인(`tests/verdict_base_S5_perf_pre`, §S5 코드를 `git stash`로 되돌린 상태에서 저장) 대비
```
SELECT      542 → 542    (+0)
OK          457 → 457    (+0)
판정불가(NOT EVALUATED)    0 → 0      (+0)
```
전이 행렬 전부 대각선, "차이 없음" (항목/샘플 딕셔너리까지 완전 동일 — Perf Data 픽스처에는 std_of가 0.0→None으로 바뀌어 값이 달라지는 케이스 자체가 없었음).

**결론: 두 데이터셋 어디에서도 `OK→SELECT` 또는 `SELECT→OK` 전이 없음. 새로 `NOT EVALUATED`로 분류된 항목도 0건** (기존에 이미 `NOT EVALUATED`였던 Test Data 2개 항목의 내부 수치만 정리됨).

## 완료 기준 답변 (숫자)

1. **0.0 을 반환하던 함수/조건 (수정 전)**: 위 §1 표. `stats_core.py` 4개 함수(6개 조건분기) + `cdf_compare_web.py`의 `max_abs_finite` 1개 함수(1개 조건) = **총 5개 함수, 7개 조건**.
2. **SELECT/OK/NOT EVALUATED 개수 변화와 전이 행렬**: Test Data — SELECT 223→223, OK 246→246, NOT EVALUATED 2→2, 전이 행렬 완전 대각선. Perf Data — SELECT 542→542, OK 457→457, NOT EVALUATED 0→0, 전이 행렬 완전 대각선. **두 데이터셋 합계 전이 0건.**
3. **NOT EVALUATED 로 새로 분류된 항목 수와 이유**: **0건.** (Test Data의 2개 항목은 §S5 이전에도 이미 NOT EVALUATED였고, 내부 수치 필드만 0.0→None으로 정리됨. Perf Data는 변화 자체가 없음.)
4. **`tests/test_stats_core.py`가 None 반환 케이스를 커버하는가**: **예.** `mean_of`/`std_of`/`zscore`/`max_abs_z` 각각의 None 반환 조건 전체에 대한 단위 테스트 + `_branch_status`/`flag_result`가 None sigma/z를 받아도 OK로 새지 않는지 확인하는 통합 회귀 테스트 3건을 신규 추가, 전체 스위트 0 실패.
