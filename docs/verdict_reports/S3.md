## Perf Data (n=3000 벤치마크 전용 합성 데이터, 회귀 기준선 없음 — 직접 계산)

`Perf Data`는 `tests/verdict_base_S2/`에 포함되지 않아(index.json 확인, data_root="Test Data"만)
`verdict_diff.py --baseline` 비교가 불가능하다. `analyze_condition()`을 fixed/grubbs 두 모드로
직접 호출해 비교함 (1 combo, 999 항목, 실측 `n_post=2910`, `n_diff=2909~2910`).

- SELECT 총계: **999 → 999 (변화 없음)**
- mea_s 만 놓고 볼 때(threshold 초과 항목 수): **999 → 45 (급감, 의도대로 동작)**
- diff_s 만 놓고 볼 때(threshold 초과 항목 수): **999 → 999 (변화 없음)**
- 원인: `tools/make_perf_fixture.py`가 Pre/Post 값을 항목별로 완전히 독립적인
  `rng.gauss(0.0, 1.0)`로 생성해 diff_s가 모든 항목에서 30~50대(정상 z-score 범위를 한
  자리 이상 초과)로 나온다. Grubbs 임계(n≈2910 → 4.292)로 올려도 diff_s가 여전히 6~12배
  초과라 diff 분기가 항상 SELECT를 유발, 항목 단위 `"result"`(mea/diff 중 하나라도 SELECT면
  SELECT)가 총계에서 안 바뀐다. diff_s 계산 자체는 §S3에서 변경하지 않았고 fixed/grubbs
  모드 간 diff_s 값이 동일함을 확인 — §S3 구현 문제가 아니라 이 합성 데이터의 성질이다.
  자세한 내용은 `NOTES.md`의 "[발견] Perf Data 는 diff_s 가 항상 30~50 대..." 항목 참조.
